# DevStack 核心体验改进方案

> 2026-10-14 全面审查：internal/ 全部 74 个 Go 文件（15,363 行）+ frontend/src 主要页面。
> 目标：不加新功能，让现有核心链路（安装 → 配置 → 启停 → 环境切换 → 卸载）流畅、诚实、可靠。

## 一、总体判断

架构骨架方向是对的：期望状态调和（engine/reconciler）+ provider 抽象 + reactive 事件推送，比 phpStudy 这类"点按钮跑脚本"的架构更有潜力。当前的问题不在骨架，而集中在一点——**状态不诚实**：大量环节向上层报告"成功/已停止/已就绪"，实际并非如此。用户感觉"用起来不顺"，本质是 UI 状态与真实世界反复脱节。

三类根因：

1. **生命周期真相缺失**：就绪判定靠固定 sleep、停止失败被吞、优雅关闭链路在 Windows 上实际失效；
2. **平台依赖脆弱**：wmic（Win11 24H2 已移除）、nginx.org 源码包（无 exe）、校验和全空；
3. **前后端契约裂缝**：事件绑定到不存在的对象、取消按钮是假的、每次事件全量重拉。

## 三、P1 —— 生命周期健壮性（修完 P0 紧接着做）

### 启动/就绪

- **就绪判定形同虚设**：服务经 `RegisterService(id,"",nil,...)` 注册，Command/Args 为空 → checkPortConflict/waitForReady 提取不到端口，固定 sleep 500ms 即判成功。MySQL 慢启动或秒退都报成功。（orchestrator/engine.go:431-513,820,841）
  → provider 暴露 `Port() / HealthCheck(ctx)` 回调，就绪判定改为真实探活（TCP 拨测/HTTP ping），失败自动回滚启动。
- **慢启动服务无监控**：Start 后立即 `FindPIDByPort`，拿不到 pid → watchProcess 不启动，健康监控与崩溃自愈失效。（manager.go:496-524）
  → 就绪探活成功后再取 pid；或注册时由 provider 直接告知。
- **无周期 reconcile**：期望状态只在用户操作时收敛，进程被外部杀掉后无主动调和，全靠前端轮询发现。（engine/reconciler.go 整体）
  → 加 2~5s 低频 reconcile 循环，顺带作为前端事件丢失的兜底真相源。
- **依赖环静默丢弃**：拓扑排序遇环，环上服务不启动也不报错。（engine.go:715-765）→ 报错并拒绝启动。
- **job 记账键不一致**：注册用 `nginx@1.26.0`，ReleasePID 用裸 kind → orchestrator 查不到，内部 PID/状态永久残留。（manager.go:656/712 vs 476、engine.go:338）

### 停止/进程

- **优雅关闭失效**：`sendCtrlC` 把目标 PID 当进程组 ID 传给 `GenerateConsoleCtrlEvent`；服务由 exec 启动、无共享控制台 → 要么失败要么把 Ctrl+C 发给自己。全链路实际退化为强杀。（process/group.go:480-497）
  → 有窗口的服务用 PostMessage WM_CLOSE，控制台服务用 Windows Job Object 的 kill-job-object + 优雅超时分级；放弃 Ctrl+C 注入幻想。
- **Stop 超时分支假成功**：`ctx.Done()` 分支直接置 Stopped、PID=0，进程可能还在跑 → 后续 Start 被幂等跳过。（engine.go:562-577）
  → 超时后复核进程存活，未死则报错。
- **Status/List 在 RLock 下写状态 + 返回内部指针**：数据竞争 + 调用方锁外可改共享对象。（engine.go:627-655）→ 返回值拷贝，修正走写锁。
- **崩溃即孤儿**：php/node 运行时只经 process.Manager 启动、不进 Job Object，应用崩溃时全部变孤儿进程。（runtime/manager.go:294、node.go:47）
- **netstat 失败返回 nil 被当"无占用"**：假阴性导致端口误判。（process/process.go:350-361）→ 失败与空闲区分开。
- **STILL_ACTIVE(259) 判活**：退出码恰为 259 或 PID 复用时误判。（process.go:240-252）

### 环境切换

- **Activate 失败留中间态**：先全停旧环境再启新，新环境失败只回滚新启单元，旧环境不恢复、activeID 未更新 → UI 显示旧环境激活但全部停机。（reconciler.go:124-154）
  → 新旧环境算交集，交集内服务跳过启停（这也是切换变快的关键优化）；失败时恢复旧环境。
- **项目依赖 Stop 报错即中止整个切换**，留下部分停止的中间态。（reconciler.go:210-237、manager.go:619-622）→ 失败收集、尽力而为、汇总报告。
- **RestoreLastSnapshot 按文件名字典序取最新**，同秒内 `-10 < -2` 恢复错快照。（snapshot.go:160-183）→ 按时间戳+数值排序。
- **environments.json 损坏静默返回空**，环境列表全丢且无感知。（environment/manager.go:137-145）→ 留损坏副本 + 明确报错。
- **datadir 按版本隔离**，切 MySQL 版本即空库，无提示。（mysql.go:22、mysql_provider.go:74）→ 切版本时提示 datadir 变化。

### 卸载/安装恢复

- **Uninstall 只停本会话记录的 PID**：上一会话残留进程（s.process=nil 但在跑）不清 → 删目录报"删除失败"且原因难懂。（manager.go:851-894）
  → 卸载前按端口+exe 路径接管清理（复用 ownedPIDByPort 逻辑）。
- **Uninstall 不从 m.services 删条目**，界面仍显示已卸载服务。（manager.go:851-894）
- **半成品安装**：崩溃残留半解压目录；`registerDefaults` 把 programs 下任意目录都标记为已安装版本（不校验 exe 存在）。（manager.go:111-134）→ 临时目录解压后原子改名 + 写安装完成标记文件。

### 前端契约

- **事件丢失无兜底**：reactive dispatch 超 64 并发即静默丢弃，UI 永久停留旧状态。（reactive/engine.go:83-98）
  → 丢弃时合并发布一次全量快照事件；配合 P1 的周期 reconcile 形成双保险。
- **错误被吞成"空态"**：Dashboard/Environment/Sites 超时/异常一律回退空数组，用户看到"暂无项目"而非报错。（Dashboard.svelte:67-68 等）→ 区分"空"与"失败"。
- **配置加载失败仍可保存**：getServiceConfig 失败时表单显示默认值 0/空，点保存会把垃圾值覆盖写回真实配置文件。（WebServer.svelte:29-38）→ 加载失败禁用保存。
- **panic recover 空实现**、**graph 依赖 ID 拼接规则不一致**（`runtime:` + map键 vs `runtime:php-版本`）导致依赖图静默退化。（reactive/engine.go:88、graph/resolver.go:58-84）

## 四、P2 —— 性能与体验优化（最后做，收益也真实）

- **Packages 页串行瀑布**：11 种软件逐个 getAvailableVersions，再逐版本 checkVersionInstalled，几十次串行 IPC，整页空白。（Packages.svelte:53-77）
  → `Promise.all` + 用 getInstalledVersions 一次拉取；SetupWizard.svelte:87-100 同理。
- **事件 → 全量重拉**：任一 reactive 事件触发 refreshSignal++，当前视图全部接口重拉，无增量。（events.ts:70-99、App.svelte:100）→ 事件带 payload 局部更新；数据层收敛为唯一 store（stores.ts 里 atom 定义后从未写入，是死状态层）。
- **Logs 页 3s 轮询全量替换 500 行数组**，无虚拟化全量重渲染。（Logs.svelte:104-107）→ 增量追加 + 虚拟滚动。
- **全屏 loading 遮罩**：任何单次启停都阻断整个 UI，且 nanoLoading 单布尔并发时先结束者提前关遮罩。（GlobalLoading.svelte、safeInvoke.ts:94）→ 按钮级 loading。
- **AssignPID 为每个进程起 500ms 轮询 goroutine** 常驻。（group.go:242-249）→ 改 WaitSingleObject 阻塞等待或显著降低频率。
- **Stop 等待循环无锁反复读 svc.PID**。（engine.go:544-579）
- **UninstallVersion 整目录拷贝备份再删**，双倍磁盘 IO。（manager.go:1195-1200）→ 改为 rename。

## 五、建议实施顺序

**里程碑 1：让核心链路诚实（P0 全部 + 就绪探活）**
做完的标志：安装要么成功要么给出可理解可重试的失败；启动"运行中"= 真在监听；停止"已停止"= 真没了；配置改了真的生效。这一步对"用起来顺不顺"的感知提升最大。

**里程碑 2：生命周期健壮性（P1）**
就绪探活 + 周期 reconcile + 优雅停服分级 + 环境切换交集优化 + 卸载接管清理。做完的标志：外部杀进程 5s 内 UI 自动纠正；环境切换不再出现半停状态；退出不损坏数据。

**里程碑 3：性能与打磨（P2）**
并行 IPC + 增量事件 + 按钮级 loading + 日志虚拟化。

## 六、贯穿性的架构建议（随里程碑逐步落地）

1. **单一状态真相源**：后端快照 + 周期 reconcile 作为唯一事实，前端所有展示都从快照派生，事件只做"提示快照变了"。消除现在 service/orchestrator/engine/reactive 四处各自记账、互相对不上的局面。
2. **provider 契约补全**：provider 接口增加 `Port()`、`HealthCheck(ctx)`、`GracefulStop(timeout)` 三个能力，engine 的通用逻辑（就绪、冲突、停止）全部委托给 provider，删掉"按名字猜依赖"、"固定 sleep"这类黑魔法。
3. **消灭 wmic/netstat 外部进程依赖**：进程枚举与端口归属改纯 Win32 API（Toolhelp32 + GetExtendedTcpTable），一并解决性能与 Win11 兼容。
